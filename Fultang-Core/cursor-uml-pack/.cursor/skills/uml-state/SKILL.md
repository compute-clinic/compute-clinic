# UML State Machine Skill

Use a state diagram only when an entity has behavior that meaningfully depends on its current state.

For each state identify:
- what the state means;
- how the entity enters it;
- valid outgoing transitions;
- triggering event/operation;
- guard when needed;
- important entry/exit behavior.

Do not confuse a status attribute with a complete state machine. The state model must explain valid transitions and prohibited transitions.
