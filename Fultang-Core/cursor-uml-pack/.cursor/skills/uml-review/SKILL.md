# UML Review Skill

Review the model like a software architect performing a design review.

## Review dimensions
1. Requirements traceability
2. Semantic correctness
3. Relationship correctness
4. Multiplicity/cardinality correctness
5. Responsibility allocation
6. Scenario coverage
7. Cross-diagram consistency
8. Notation correctness
9. Readability
10. Unjustified assumptions

For each issue explain:
- what is wrong;
- why it matters;
- what evidence supports the correction;
- the smallest useful correction.

Do not rewrite the entire model when a local correction is sufficient.
