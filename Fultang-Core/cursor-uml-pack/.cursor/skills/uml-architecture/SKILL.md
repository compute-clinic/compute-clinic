# UML Architecture Skill

Use component diagrams to show deployable/reusable software units and their provided/required interfaces.
Use package diagrams to organize model elements and dependencies.
Use deployment diagrams to show runtime nodes, execution environments, and deployed artifacts.

Do not put domain entities into a component diagram unless their architectural role is actually relevant.
Do not invent microservices just because the system is large.

Architecture should be traceable to actual functional and non-functional needs.
