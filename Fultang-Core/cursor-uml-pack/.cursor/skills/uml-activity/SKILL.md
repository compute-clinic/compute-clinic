# UML Activity Diagram Skill

Use activity diagrams to explain workflow and process logic.

Identify:
- initial node;
- actions;
- decisions and guards;
- merge points;
- fork/join for parallel work;
- final nodes;
- swimlanes when responsibility allocation matters.

Do not confuse an activity diagram with a screen-by-screen UI flow. Model business actions and decisions first.

Every guard should describe a meaningful condition. Avoid contradictory or overlapping guards unless intentionally modeled.
